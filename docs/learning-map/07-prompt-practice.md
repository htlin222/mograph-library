# 提示詞實戰：合集 × 學習地圖

分析 [awesome-opus5-5-videos](https://github.com/yihui-dev/awesome-opus5-5-videos) 的 703 條提示詞後，結論是：三分之二的提示詞只交代了描述公式九欄中的兩欄以下，而且題材擠在同幾類。這份地圖的語彙正好補上缺的欄位，大詞索引則指出還沒人做的題材。

## 這個合集是什麼

703 條提示詞、616 位作者，九月收 375 條、十月收 328 條；最後一次整理（2026-10-13）刪掉 150 條不是單純用 Opus 5.5 做出來的作品。數字取自 `data/videos.json`，以下分析都以這份檔案為準。

| 類別                   | 條數 | 最常見的技術標籤                  |
|------------------------|------|-----------------------------------|
| 動態設計 motion        | 369  | Canvas 142、SVG 124、GSAP 64      |
| 3D                     | 117  | Three.js 46、Canvas 34、著色器 33 |
| 解說 explainer         | 116  | Canvas 41、SVG 35、Three.js 19    |
| 互動與遊戲 interactive | 101  | Canvas 50、Three.js 42、著色器 26 |

- 技術標籤前五名：Canvas 267、SVG 183、Three.js 131、著色器 92、GSAP 86；標了音訊（audio）的只有 39 條。

- 207 條（29%）標為提示詞不完整，只收到原帖文字或片段；有現場重製版的是 418 條。

- 提示詞長度中位數 221 個字元（約 35 個英文單字），132 條不到 100 個字元。

**原理就是地圖的〇與五。** Opus 5.5 只輸出文字，所以它寫的是一個 draw(t) 或 seek(t) 函式：給一個時間，畫出那一格。瀏覽器自動化工具再逐格擷取、編成影片。這和本片的 frame(t) 場景契約、無頭算圖加 ffmpeg 的管線是同一件事，細節見主分頁的〇 地基與五 製作管線，以及語彙四的〈程式動態的常用動詞〉。

## 提示詞缺什麼

把描述公式的七欄拆成九項（風格與聲音分開，再加規格），逐條檢查提示詞提到哪幾項。最少被寫進去的三項，正好是決定「動得好不好看」的那三項。

> 📊 圖表（互動版見原文件）：data/videos.json（commit 92aee2f，2026-10-13）· 703 條 · 中英關鍵字比對，為近似值

703 條裡有 465 條（66%）只交代了 0–2 項，交代 6 項以上的只有 78 條。沒寫的欄位就交給模型自己決定，而模型的預設選擇很接近，這是成品看起來大同小異的主因。補上藍色三項最快拉開差距：緩動與物理感的詞在語彙一，鏡頭與轉場的詞在語彙三。

## 選題：哪裡擠、哪裡空

同質化來自題材擠在一起。把大詞索引裡的題材拿去比對 703 條提示詞，最擠的是 3D 場景、介面、解說與產品發表，而地圖上不少大詞幾乎沒人碰。

> 📊 圖表（互動版見原文件）：data/videos.json（commit 92aee2f，2026-10-13）· 703 條 · 中英關鍵字比對，為近似值

《Motion, in Code》的 02、03、04、10 四段剛好都落在藍色區。選題時可以從藍色區和大詞索引的生成演算法、字體玩法、材質與光線三組找起。少人做也可能代表比較難做或不好傳播，先用一段 5 秒試做確認效果。

措辭也很集中：提到「motion design」的 71 條、「15 秒」的 55 條、「showreel」的 45 條、「world-class／professional」的 29 條。

## 升級示範：一句話 → 描述公式

下面是合集裡最典型的一句話提示詞，以及用描述公式改寫後的版本。改寫版把九項都填了，模型就沒有「預設」可以退回去。

**原版**（roundtablespace-232366，類似的还有至少 5 條）：

``` text
make a 15-second motion graphics showreel that proves what an incredible motion designer you are, go all out.
```

**改寫版**：

``` text
做一支 15 秒、直式 1080×1920、30 fps 的動態設計 showreel，主題是「時間是一個變數」。

結構（120 BPM，剪接點都在落拍）：
1. 0–4 秒：一顆珊瑚紅的球從左上落下，落地壓扁 40%、空中沿速度方向拉長，身後留 6 個洋蔥皮殘影；每次落地對一聲玻璃鐘聲。
2. 4–8 秒：MOTION 六個字母用可變字體的寬度軸在 62–125 之間每拍換一次；最後 1 秒鏡頭指數加速，穿過字母 O 的中空處。
3. 8–12 秒：O 的中空處長出 Gray–Scott 反應擴散的珊瑚紋，4 秒內長滿畫面。
4. 12–15 秒：紋理轉成兩色孔版印刷（螢光粉＋鈷藍，錯位 4 px），收在片尾字卡。

質感：進場一律 ease-out expo 0.4 秒；彈簧阻尼比 0.5，晃兩下停；不要線性等速。
構成：對齊 12 欄網格，左右留 84 px，上下各留 15% 安全區。
轉場：段落之間只用動作匹配或穿越轉場，不用淡入淡出。
風格：墨黑底、米白字、只用珊瑚紅一個強調色；細顆粒 4%；不要霓虹、不要光暈。
聲音：用 Web Audio 合成大鼓、貝斯、FM 玻璃鐘聲，整體 −14 LUFS。

做法：每段寫成 frame(t) 純函數，任何一格都能直接算出。每完成一段，渲染 5 張縮圖並排檢查、列出問題再修，沒有問題才做下一段。
```

| 補上的內容                         | 欄位       | 詞從哪裡來                                     |
|------------------------------------|------------|------------------------------------------------|
| 1080×1920、30 fps、−14 LUFS        | 規格       | 語彙四 · 規格                                  |
| 120 BPM、落拍、每段秒數            | 時間       | 語彙一 · 時間與節奏                            |
| 擠壓伸展、洋蔥皮殘影               | 動作、質感 | 語彙一 · 動畫原則                              |
| ease-out expo、阻尼比 0.5          | 質感       | 語彙一 · 緩動曲線與彈簧                        |
| 可變字體寬度軸、反應擴散、孔版錯位 | 主體、風格 | 大詞索引 · 字體玩法、生成演算法；語彙二 · 後製 |
| 12 欄網格、安全區                  | 構成       | 語彙三 · 畫面構成                              |
| 穿過字母 O、動作匹配               | 鏡頭、轉場 | 語彙三 · 鏡頭運動、轉場                        |
| 一個強調色、「不要霓虹」           | 風格       | 語彙三 · 色彩；語彙五                          |

## 可重複使用的提示詞範本

把「」裡的內容換成你的選擇即可；前半是描述公式，後半是程式路線的做法與自我檢查，後半可以每次照抄。搭配較高的推理等級（xhigh 或 max）效果最好。

``` text
「片名／主題」：做一支「秒數」秒、「比例與解析度」、「影格率」的「類型，去大詞索引挑」。

結構（「BPM」，剪接點在「落拍／每幾拍」）：
1. 「開始–結束秒」：「主體」「怎麼動，含數字」；「和哪個聲音對位」。
2. ……

質感：「曲線名稱或彈簧參數」；「動畫原則，如預備動作、跟隨重疊」。
構成與鏡頭：「網格、留白、安全區」；「鏡頭運動」。
轉場：「轉場名稱」；不要「不想要的轉場」。
風格：「流派或參照」、「色盤，最多 4 色」、「質感」；不要「常見但不想要的效果」。
聲音：「樂器與音效」，整體「響度，如 −14 LUFS」。

做法：
- 只用程式產生畫面與聲音（「Canvas 2D／SVG／WebGL／Three.js」），不用任何圖片、影片或音效素材。
- 每段寫成 frame(t) 純函數：同一個 t 永遠畫出同一格，隨機數用固定種子；物理模擬用固定步長。
- 每完成一段，渲染 5 張縮圖並排打開來看，列出問題（重疊、裁切、節奏、配色、可讀性）再修，沒有問題才做下一段。
- 最後用無頭瀏覽器逐格擷取，以 ffmpeg 編成 MP4，並量測響度。
- 不用問我，遇到選擇就照上面的規格做判斷，最後列出你做了哪些判斷。
```

## 用法：合集 × 地圖的五步

合集當「參考庫」，地圖當「拆解與重組的工具」：看別人的作品，用地圖的詞說出它做了什麼，再換掉幾個詞變成自己的。

1.  **挑一支**：在 `data/videos.json` 或 Skillry 頁面用類別篩選，只看沒標「提示詞不完整」的 496 條。

2.  **拆解**：看原片，用描述公式九項逐項寫出它實際做了什麼，詞從大詞索引與語彙分頁找。原提示詞沒寫、但片子裡有的，就是模型自己補的預設。

3.  **換詞**：至少換掉兩項——主題從上方「選題」圖的藍色區挑，再把質感、鏡頭、轉場其中一項寫成具體數字。

4.  **套範本**：填進上方範本，用高推理等級執行，讓模型逐段渲染縮圖、自評再修。

5.  **歸檔**：把成品和提示詞一起放進作品集（主分頁七 創作者實務），註明參考了哪一支原片。

## 要留意的地方

- **導流**：README 的主要連結都指向作者經營的 Skillry（帶追蹤參數）。合集本身是 MIT 授權，直接用 GitHub 上的 `prompts/` 與 `data/videos.json` 就夠，不必留言「VIDEO」或註冊。

- **不完整的提示詞**：207 條只有原帖文字或片段，照抄不會得到原片的效果。

- **一句話提示詞會擞臉**：大多數欄位交給模型決定，成品自然接近；差距來自選題和補齊的欄位。

- **能力邊界**：程式路線擅長幾何圖形、動態文字、介面與程序生成的紋理；寫實人物與複雜實景不是強項。

- **統計法**：本頁兩張圖用中英關鍵字比對，是近似值；一條提示詞可以同時計入多項。

- **引用的條目不一定還在**：作者會清理混入其他工具的作品。例如外部文章提到的 levabashidze 條目，在目前的主分支已經找不到。
